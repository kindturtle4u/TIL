# 5. 디자인시스템 반영과 검증

## 5.1 이론-디자인시스템과 Hooks검증
- `design.md`: 디자인 이미지를 테그스트 시각 명세로 변환할 수 있다.
- 디자인 시스템 세분화: `colors.md`, `typography.md`, `spacing.md`, `components.md`로 구조화 할 수 있다.
- Skill + PostToolUse Hook: 작성된 코드가 디자인 시스템을 자동으로 따르게 만들 수 있다.

### 디자인 이미지로는 부족하다
- 이미지 한장으로 일관된 UI를 만들 수 없다. - 매번 색,간격,폰트가 달라진다.
  * 디자인 이미지 (Figma / Stitch / 스크린샷)
  * 디자인 시스템 생성 (md 파일들)
    + colors, typography, spacing, components
  * Calude Code에 추가 (Skill / CLAUDE.md / hook)
- 이미지를 시스템(문서)으로 옮겨야 AI가 일관되게 따른다.

### Claude Code Hook - 자동 실행 스크립트
- PreToolUse: 도구 실행 전 (차단 / 검증)
- PostToolUse: 도구 실행 후 (검사/포맷/린트)
- UserPromptSubmit: 프롬프트 제출 시 (컨텍스트 주입)
- Stop: 응답 종료 시 (마무리 작업)
- `.claude/settings.json`에 정의 -> 사람이 잊어도 시스템이 강제

### PostToolUse Hook 설정 예시
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "note scripts/check-design-system.js"
          }
        ]
      }
    ]
  }
}
```
